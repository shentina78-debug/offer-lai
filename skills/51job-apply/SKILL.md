# 前程无忧入口

平台键为 `51job`，中文别名为“前程无忧”。先读[共用流程](../../APPLICATION_GUIDE.md)，本文件只维护网站分支。实际操作与命令见[前程无忧投递步骤](前程无忧投递步骤.md)。当前对话GPT完成岗位方向判断、自然语言条件解释和匹配评分，固定程序处理正常网页动作及共用检查。

- 只读同一个 `state.settings`、`state.resume`，评分只读同一份[岗位匹配评分标准](../../岗位匹配评分标准.md)。最低日薪、天数、期限、排除项与最低分均复用原检查，不另存平台版条件或简历。
- **只有前程无忧**采用：黄色“校招”直接忽略、不打开；绿色“实习”或已核实无“校招”标签的岗位可进入详情继续核验。无标签不是自动达标。DOM无法识别图形标签时，一次截图批量核对当前列表，使用带本页指纹的 `reviewLabels`；不把未读到当作没有。
- 搜索顺序：工作台关键词→点击搜索→等新结果→核对城市（本次用户要求上海）→工作类型“实习”→“最新优先”。城市/类型与当前工作台冲突时先说明，不覆盖设置。程序当前只支持单次一个已保存城市、一个已保存关键词，多项按需分别搜索。
- 进入详情先查“已投递”和有效状态。完整JD硬筛通过才读取简历并按65＋35评分，交回最终数值；程序比较工作台最低分。2026-10-24演示跳过评分是一次性指令，不能成为自动流程默认值。
- 达标后选择附件 **“综合能力简历”**。它与评分用的当前保存简历分别记录，不凭附件名称声称内容一致。选中证据不可读时不发送，交Agent核对。
- 点击“发送”前先通过共用主干持久登记尝试并复查；每个attempt只点击一次。延迟、超时、会话重置后只观察原尝试，不重发。
- 本平台成功为：本次发送后在 `jobs.51job.com/applysuccess.php?jobid=本岗位ID` 看到明确“投递成功”。详情页一开始的“已投递”是跳过条件，不计为本轮新增成功；发送后仅见“已投递”仍不足以自动冒充本次成功。
- 结果返回共用 `complete/sync`，用原 `/api/records` 汇总到原HTML。同步失败只补记录，不重新投递。公司分类仍由原本地名单程序完成。

正常动作调用本平台模块，不反复逐按钮询问模型。DOM连接失败时保留当前页面与已登记尝试，报告缺少的能力；不要重复建立连接或改用网站私有接口。遇到登录、验证码、新表单、标签/附件证据不明或其他陌生状态，交回Agent按实际页面处理。

本地模拟验证与真实网站验证必须分别报告；不能将命令耗时或模拟通过当作整轮投递速度达标。
