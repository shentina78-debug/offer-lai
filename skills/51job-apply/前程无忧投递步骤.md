# 前程无忧网页流程与固定调用

仅用于 `51job`，依据2026-10-24用户现场教学：搜索→关键词搜索生效→上海→实习→最新优先→跳过黄色校招→候选详情→共用硬筛→共用评分→立即投递→综合能力简历→发送→成功回执→共用入库。实习僧的中文附件、补充信息、结果弹窗和JS桥均不在本平台使用。

## 文件边界

| 文件 | 职责 |
| --- | --- |
| `platforms/job51.py` | URL/ID、详情字段解析、平台标签排除、准备及成功证据核对 |
| `scripts/submission_flow.js` | 经CUA读取当前渲染DOM，搜索、筛选、列表、详情、附件与发送状态机 |
| `scripts/submission_bridge.mjs` | CUA模块连接共用本机CLI；归档观察、登记尝试、只发送一次、结果入库与重试记录 |
| `submission_profile.json` | 本网站控件文字及目标附件名；不保存薪资、天数、期限或独立简历正文 |
| `SKILL.md`与本文件 | 平台专用调用说明与已验证的网站顺序 |

共用文件：`application_run.py`负责运行与交接；`application_batch.py`负责原硬筛/门槛/同步；`application_guard.py`负责原去重；`APPLICATION_GUIDE.md`和`岗位匹配评分标准.md`负责唯一业务/评分规则。前端、入库服务、企业名单、实习僧包继续复用原实现。

## 本机准备

在项目目录，用README指定的Python运行时调用以下命令；新运行目录不得覆盖旧运行。

```sh
python3 application_run.py platform 前程无忧
python3 application_run.py start runs/本轮前程无忧 --platform 51job --limit 10 --check-service
python3 application_run.py website-input runs/本轮前程无忧
python3 application_run.py session-code --platform 51job
```

`website-input`读取当前已保存条件，不包含简历或API密钥。尚有未核实尝试时停止新搜索；已达数量目标返回done。不要每岗重新读取未变的说明、简历、标准。

## CUA绑定及搜索

读取本轮CUA浏览器说明，按最新标签清单绑定实际前程无忧搜索页，命名句柄 `job51Browser`、`job51Tab`。不要使用以前会话的数字浏览器ID；不得经shell、HTTP客户端、私有API或浏览器内部状态读取招聘页面。执行 `session-code` 返回的代码，再设置：

```js
var job51Run = 'runs/本轮前程无忧';
// keyword/city 必须选自website-input返回的工作台值，不固定写“市场分析”。
nodeRepl.write(await job51Session.search(job51Run, keyword, city));
```

程序按已确认顺序操作；不以网站“月薪范围”替代最低日薪，不设置学历/专业/毕业年份作为淘汰筛选。当前单次搜索一个城市、一个词；多词、多城市由Agent组织各次搜索、合并候选，达到数量上限即停止，不开启无限搜索。

## 列表、标签与打开详情

`search/list`返回每条候选的 `candidateKey`、岗位、公司、真实链接（若页面有）、标签证据和action：

- `skip_campus`：本平台黄色“校招”，绝不打开。
- `candidate`：标签已核实，可由Agent判断岗位方向后打开；后面仍需硬筛和评分。
- `needs_label_review`：图形标签无法从渲染DOM确定。Agent通过当前页截图批量判断，不点击岗位。调用以下接口，附现场依据；列表变化后指纹失效。

```js
await job51Session.reviewLabels(job51Run, snapshotKey, [
  {candidateKey, campus: false, evidence: '当前列表截图中，该岗位名称旁为绿色实习标签'}
]);
nodeRepl.write(await job51Session.open(job51Run, candidateKey));
```

不覆盖程序已经识别出的“校招”。程序只点岗位名称，不点列表“投递”。部分卡片没有可读的详情链接，不编造ID；打开后读取真实URL，绑定唯一新增的岗位详情标签，再做本地去重。

`open`核对打开后的岗位名和公司，归档页面事实，用共用 `detail`命令保存 `岗位ID.job.json` 并返回硬筛结果。已投递或失效跳过；列表筛选为上海也不能代替详情实际地点核验。

## 硬筛与评分完整保留

程序提取明确日薪、每周出勤、实习月数；区间最低要求按下限。月薪/年薪保留原单位，绝不换算日薪，也不改写成“未公开”。模糊的“长期实习”等不猜月数。字段缺项或冲突时，Agent读取原JD核对并结构化，保留相应原文依据。2026-10-25用户更新：完整读取后岗位未详细写明地点、出勤或实习期限等非薪资硬指标，默认符合，继续评分，不猜具体数值；明确冲突或读取失败仍先核实。日薪下限低于150元仍不合格；薪资缺项及月薪年薪沿用共用薪资规则。

每周岗位最低要求≤工作台可出勤天数；岗位最低期限≤工作台可实习月数；日薪区间下限≥工作台最低日薪。面议/未公开按共用开关处理。地点、岗位类型、工作方式、排除词均用共用规则；毕业年份等仍按原评分附加项处理。

```sh
python3 application_run.py score-input runs/本轮前程无忧 runs/本轮前程无忧/岗位ID.job.json
# 当前对话GPT收到完整JD、同一份简历及唯一评分标准，完成65＋35分析后只交回真实最终数值。
python3 application_run.py rate runs/本轮前程无忧 runs/本轮前程无忧/岗位ID.job.json 真实最终分数
```

低分走共用 `finish` 保存待审核，评分异常按共用流程存null，不伪造分数。只有真实达标的交接可以进入自动投递；不得把演示时“假设达标”写成默认开关。

## 附件、发送与收尾

```js
nodeRepl.write(await job51Session.submit(job51Run, '真实岗位ID'));
```

一次调用内部执行：最新交接→目标详情→已投递/失效检查→打开附件弹窗→选择“综合能力简历”→核实唯一选中附件与发送按钮→共用arm持久登记→共用confirm门槛/材料/数量复查→发送一次→只读核对成功回执→共用complete保存并同步。

选中证据来自标准checked/aria-checked或页面实际渲染的橙色实心单选圆点，不能凭“点过”推断。控件不唯一、有新输入项或无法确认选中状态时停止。程序不猜坐标，不点标题来核对选中状态。

- `continue_prepare`：同一会话续接已打开/已选择的弹窗，不重复打开、重复切换。
- `observe_result`或`needs_reconciliation`：保留尝试，只核查。
- `retry_record`：本地已有页面证据，只重新消费原结果，不重新发送。
- `sync_pending`：只补原入库，不重复投递。

```js
nodeRepl.write(await job51Session.inspect(job51Run, '真实岗位ID'));
```

会话重置后，重新绑定本岗位当前标签、重新加载模块，`submit`会先查询磁盘登记：有原尝试则自动转inspect，禁止再次发送。若页面已丢失，交Agent核查原尝试；不要通过重新提交寻找成功页。

成功必须同时有本次尝试、匹配岗位ID的 `/applysuccess.php?jobid=…` 和页面明确成功文字；单独页面URL或一开始的“已投递”都不计本轮新增。原始详情链接存入记录，成功页URL只作证据。无需为了成功重复打开详情。

```sh
python3 application_run.py sync runs/本轮前程无忧
python3 application_run.py report runs/本轮前程无忧
```

仍使用同一HTML和 `/api/records`，稳定ID为 `51job:岗位ID`，不会和实习僧记录或尝试相撞。企业分类只用原本地名单。300秒是软目标；命令耗时、会话耗时、整轮开始到最后成功的耗时应分开报告。

## 验证边界

2026-10-24用户带操作的正常路径已经真实走通（岗位174008722）。新增代码使用本地模拟验证，不因此宣称已通过新程序的真实网站端到端测试或速度达标。当前浏览器DOM绑定出现过超时/Debugger unattached；恢复连接后应先只读检查列表标签、选中标记与已投递岗位，确认后再在用户授权范围内测试真实投递。未知错误页暂不自动解释成明确失败，保留尝试交Agent核查。
