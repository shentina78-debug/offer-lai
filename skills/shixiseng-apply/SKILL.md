# 实习僧平台入口

适用平台仅为 `shixiseng`（实习僧）。共用业务规则已归入[招聘投递共用流程](../../APPLICATION_GUIDE.md)；从旧入口进入时也先读该共用流程，规则不另存一套。网页操作、配置和顺序仍沿用下面原文件，本次没有重写网页程序。

执行前读[固定执行与五分钟目标](fast-path.md)。读取顺序、搜索关键词、硬筛、65＋35评分、最低匹配分、同一共享简历、异常处理及入库规则均按共用流程；原命令继续有效，默认仍为实习僧。

## 实习僧专用材料及适配入口

- `platforms/shixiseng.py`：原岗位URL/ID识别、原CUA AX列表解析、原准备与结果证据检查；调用下面原文件，不复制网页状态机。
- [实习僧投递步骤](../../实习僧投递步骤.md)：原按钮、弹窗、中文附件、补充信息及结果判定标准，按原时机读取。
- [submission_profile.json](submission_profile.json)：原中文附件和已确认补充信息，数值及版本不变。
- [submission_flow.js](scripts/submission_flow.js)：原网页状态机，保留原文件和内容。
- [submission_bridge.mjs](scripts/submission_bridge.mjs)：原实习僧CUA会话桥，保留原文件和内容。它不是所有平台共用的网页桥。

## 搜索、详情及已改进的问题如何保留

- 搜索和打开详情仍由Agent通过CUA执行：按已保存关键词分别搜索、设置网站能等价表达的筛选条件、核对当前真实页面/岗位链接。没有新写一套实习僧搜索驱动，也没有把现有固定投递改成Agent逐按钮操作。
- `application_run.py list` 仍调用原AX列表解析；字体乱码不猜测，缺项留待完整详情。Agent读取并结构化详情，按原规则核对 `delivered/expired`，不为判定状态点击“投个简历”。不把URL路径或列表摘要当成完整JD。
- 投递仍按原顺序执行：刷新交接 → 打开原投递界面 → 核对中文附件及已确认补充信息 → 先登记尝试 → 提交前检查 → 确认仅一次 → 真实结果核验 → 关闭可识别结果界面 → 共用落盘入库。
- 弹窗/表单分段加载、附件勾选延迟继续同一次操作，不重复打开或切换；结果未出现只观察，不重新确认。这些实习僧页面判断仍在原flow/bridge中。
- 中文附件、`radio-choosed.png`、AX的“投递成功/投递失败”及 `clickedConfirm` 证据只在本平台适配器检查。别的平台必须用其真实证据，不能借这些字段判定成功。
- 中英文简历完善要求、英文简历拒绝仍按原流程跳过；不修改英文简历。未知弹窗、新必填、登录或验证码按原方式交回Agent处理。
- 5分钟仍为软目标，超时提醒并继续；明确失败继续下一岗；结果不明保留日志禁止重投；同步异常只补记录，不再投递。

达标后继续优先使用原 `session-code` 加载的 `submissionSession.submit`。`continue_prepare`续同一会话；`observe_result`只读核查；正常动作不增加模型往返。详细命令、异常续接与计时说明全部保留在原fast-path，避免重复维护。

历史 `APPLICATION_WORKFLOW.md` 仍只供历史参考。
